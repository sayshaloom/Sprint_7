# Sprint 7. Автотесты API сервиса «Яндекс.Самокат»

Проект с автоматизированными тестами для API учебного сервиса аренды самокатов.
Проверяются создание и авторизация курьера, а также создание заказа и получение списка заказов.

Тестовый стенд: `https://qa-scooter.praktikum-services.ru`

## Стек

- Python 3
- pytest — запуск тестов
- requests — HTTP-запросы
- Faker — генерация тестовых данных
- allure-pytest — отчёты Allure

## Структура проекта

```
Sprint_7/
├── api_client/
│   └── scooter_api.py        # клиент API: методы для каждого эндпоинта
├── tests/
│   ├── test_create_courier.py  # тесты создания курьера
│   ├── test_login_courier.py   # тесты авторизации курьера
│   └── test_orders.py          # тесты заказов
├── conftest.py               # фикстуры (клиент, данные курьера, очистка)
├── data.py                   # URL, эндпоинты и ожидаемые тексты ответов
├── requirements.txt          # зависимости
└── README.md
```

## Что проверяется

**Создание курьера** (`test_create_courier.py`)

- успешное создание курьера (201, `{"ok": true}`);
- ошибка при создании двух одинаковых курьеров (409);
- ошибка при создании без поля `login` (400);
- ошибка при создании без поля `password` (400).

**Авторизация курьера** (`test_login_courier.py`)

- успешная авторизация (200, в ответе есть `id`);
- ошибка при неверном пароле (404);
- ошибка при несуществующем логине (404);
- ошибка при отсутствии поля `login` (400);
- ошибка при отсутствии поля `password` (400, см. «Известные проблемы»).

**Заказы** (`test_orders.py`)

- успешное создание заказа с параметризацией по цвету самоката: `BLACK`, `GREY`, оба цвета, без цвета (201, в ответе есть `track`);
- успешное получение списка заказов (200, в ответе есть `orders`).

## Как устроены тесты

- **Клиент API** (`api_client/scooter_api.py`) инкапсулирует все запросы. Каждый метод обёрнут в `@allure.step`, поэтому шаги видны в отчёте.
- **Фикстуры** (`conftest.py`):
  - `api_client` — один экземпляр клиента на весь прогон;
  - `courier_payload` — случайные данные курьера, сгенерированные Faker;
  - `registered_courier` — курьер, уже зарегистрированный на сервере;
  - `cleanup_courier` — после теста логинится под созданными курьерами и удаляет их, чтобы не засорять стенд.
- **Тестовые данные** (URL, эндпоинты, ожидаемые сообщения об ошибках) вынесены в `data.py`.

## Установка и запуск

1. Создай и активируй виртуальное окружение.

   Windows (PowerShell):
   ```
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   ```

   Linux / macOS:
   ```
   python3 -m venv .venv
   source .venv/bin/activate
   ```

2. Установи зависимости:
   ```
   pip install -r requirements.txt
   ```

3. Запусти тесты:
   ```
   pytest -v
   ```

## Отчёт Allure

Запуск тестов с сохранением результатов:
```
pytest -v --alluredir=allure-results
```

Открыть отчёт в браузере (нужен установленный [Allure Commandline](https://allurereport.org/docs/install/)):
```
allure serve allure-results
```

## Известные проблемы стенда

- **Логин курьера без поля `password`.** Сервер возвращает ответ 504 Gateaway time out (запрос зависает). Тест `test_courier_login_without_password_error` помечен как `xfail`: ожидаемое поведение по спецификации — 400 и сообщение «Недостаточно данных для входа». Когда баг исправят, тест начнёт проходить (XPASS).
